## An unconfirmed dispatched P&R run blocks later runs

A later `rb pnr` of a configuration refuses to start while an earlier [dispatched](https://rtl-buddy.github.io/rtl_buddy/dev/concepts/pnr/#dispatch-the-stages-to-slurm) run's stage jobs may still be queued and it cannot confirm they have left: while `squeue` does not answer, on a host without `squeue` while that run's `dispatch/` record changed within the total `time` its jobs asked for, and for up to 11 minutes while a submission of that run has no answer from `sbatch`. On a host without `squeue` a record older than that only warns, though a job can wait in the queue for any time before it starts. Run `rb pnr` where `squeue` answers, or, once the jobs have ended or the submission is known to have died, remove the `checkpoints/<run id>/dispatch/` directory the refusal names.
