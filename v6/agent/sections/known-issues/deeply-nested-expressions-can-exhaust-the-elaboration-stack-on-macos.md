## Deeply nested expressions can exhaust the elaboration stack on macOS

`max_parse_depth` lifts slang's parser nesting limit, but the passes after the parser still recurse over the same expression, and `rb elab`'s analysis pass runs on a slang thread pool whose threads take the platform default stack — 512 KiB on macOS against 8 MiB on Linux. On macOS a chain of roughly 400 nested conditional expressions therefore kills the worker with no diagnostic, and the run reports `elaboration worker did not produce a result`; the identical source elaborates on Linux. Gate generated RTL that deep on Linux, or reduce the generated nesting. Nesting that costs less per level, such as parentheses, is unaffected. See [Model Elaboration](https://rtl-buddy.github.io/rtl_buddy/v6/concepts/elaboration/).
