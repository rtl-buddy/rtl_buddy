# Audit The Documentation

This audit covers general documentation reviews and checks that new features
are documented. Judge explanatory pages and reference pages by different
standards: applying one standard to both produces misleading findings.

## Classify The Pages

Concept and guide pages under `concepts/`, plus `quickstart.md`, `install.md`,
`agents.md`, and `migrations.md`, teach a reader how and why to use a feature.
Each should:

- Open with what the feature is and when or why to use it.
- Build from motivation to mechanics.
- Use scannable section headings.
- Include runnable examples for non-trivial patterns.
- Stay focused on one concept and avoid unexplained field enumeration.

Reference pages are intentionally exhaustive. Evaluate
`reference/cli.md` and `reference/yaml.md` for accuracy and completeness rather
than narrative flow. `reference/cli.md` is generated by
`scripts/gen_cli_reference.py` and must not be edited by hand.

## Run A General Audit

1. List the shipped pages with `uv run rb docs list`.
2. Classify each page as a concept/guide or reference page.
3. Apply the matching criteria below.
4. Compare `reference/cli.md` with `uv run rb --help` and relevant command help.
5. Compare `reference/yaml.md` with `src/rtl_buddy/config/` for missing fields.

## Run A Targeted Audit

For a new feature or pull request:

1. Identify the user-visible behavior in the diff.
2. Check that a concept page explains it; flag missing conceptual coverage.
3. Check that new YAML fields appear in `reference/yaml.md`.
4. Check that new CLI options appear in `reference/cli.md`, regenerating the
   page with `uv run python scripts/gen_cli_reference.py` when needed.

Follow [Documentation Guidelines](docs.md) for authoring and validation rules.

## Evaluation Criteria

| Concept or guide criterion | Standard |
|---|---|
| `description:` frontmatter | Required; CI enforces it. |
| Opening paragraph | Answers what this is and when to use it before mechanics. |
| Section structure | Uses an `##` per major concept and scans cleanly. |
| Runnable examples | Makes every non-trivial config or command copy-pasteable. |
| Cross-references | Links to reference pages instead of repeating schemas. |
| Field lists | Adds prose that explains intent around enumerations. |

| Reference criterion | Standard |
|---|---|
| `description:` frontmatter | Required; CI enforces it. |
| `reference/cli.md` | Matches the current CLI exactly. |
| `reference/yaml.md` | Covers every field and marks required versus optional. |
| Examples | Includes a complete working example for each major config block. |

## Report The Audit

For a general audit, report `Page | Type | Criterion | Status | Note`. For a
targeted audit, list each gap with one recommended action. Treat missing
`description:` frontmatter as CI-blocking. Follow [Code Reviews](reviews.md) for
pull request scope and feedback rules.
