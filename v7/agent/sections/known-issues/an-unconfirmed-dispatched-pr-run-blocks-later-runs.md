## An unconfirmed dispatched P&R run blocks later runs

While an earlier [dispatched](https://rtl-buddy.github.io/rtl_buddy/v7/concepts/pnr/#dispatch-the-stages-to-slurm) run's stage jobs may still be queued, a new `rb pnr` of the same configuration refuses to start. It also refuses when it cannot confirm the jobs have left: while `squeue` does not answer, on a host without `squeue` while that run's `dispatch/` record changed within the total `time` its jobs asked for, and for up to 11 minutes while an `sbatch` submission has no answer. Run `rb pnr` where `squeue` answers, or, once the jobs have ended, remove the `checkpoints/<run id>/dispatch/` directory the refusal names.
