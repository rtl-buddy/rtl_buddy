## How the SDC is read

`rb` reads SDC and XDC text with one of two readers. `rb tool-check` names the active one under `In-process readers`.

- **`tcl`**: a safe Tcl interpreter, so line continuations, braces, nested collections, `$variables` and `[expr ...]` read as they do in Vivado and OpenSTA. It has no `exec`, `open`, `file`, `socket`, `cd`, `glob` or `source`; `source` includes are not followed, so name the included file directly. The synthesis clock-period read is the exception below.
- **`tokenizer`**: the fallback when no Tcl interpreter can start, typically a Python without `_tkinter`, or when the interpreter refuses a file. It splits words but evaluates nothing, so `-period $p` or `-period [expr ...]` is reported as unevaluated, and a command inside a `foreach`, `if` or `proc` body is not read. Install tkinter to restore the `tcl` reader: `uv python install --managed-python`, `brew install python-tk@<X.Y>`, or `dnf install python3-tkinter`.

Either reader returns syntax only. `get_ports`, `get_cells` and `-filter` collections stay opaque names, because OpenROAD or Vivado resolves them against a netlist.

When `rb synth` reads the SDC for ABC's delay target, it also:

- follows `source`, relative to the sourcing file's directory and then the working directory. As in Tcl, the sourced file runs in the caller's scope: it reads the sourcing file's variables, arrays and procs, and what it sets stays visible to the caller. A platform SDC can therefore set per-clock periods and source a shared SDC that creates the clocks. `[info script]` names the file being read, and `file dirname`, `join`, `normalize`, `tail` and the other path subcommands answer as Tcl's do, so `source [file join [file dirname [file normalize [info script]]] clocks.sdc]` works. The `tokenizer` follows only a literal path. An include it cannot read warns `constraints.source_unreadable`.
- re-reads a file the interpreter refused with `get_ports`, `get_pins`, `get_cells`, `get_nets`, `get_clocks` and `all_*` returning their name arguments as a list, so a `proc` or `foreach` over `[get_ports {a b}]` runs. `get_full_name`, `get_name` and `get_object_name` return the name they are given. `get_property` or `get_attribute` of the `period` of an object `get_clocks` returned gives the `-period` of the clock the SDC created by that name, so a helper such as `expr {[get_property [get_clocks clk] period] - 100}` evaluates. Any other property, a clock the SDC did not create, or an object another query returned, such as `[get_ports clk]` for the clock's source port, is not answered. The reader has no design, so a check such as `[get_property $p direction] ne "input"` cannot be answered: in the re-read, a check raised with `error`, `throw` or `return -code error` is skipped and the file carries on after it. Each skipped check is logged at DEBUG as `constraints.tcl_check_skipped`, and each file with skipped checks warns once with their count as `constraints.tcl_checks_skipped`.
- in the re-read, skips a top-level command of the SDC or of a sourced file that raises any other Tcl error, such as an unset variable or `expr` on a property the reader cannot answer, or a `break` outside a loop. Commands separated by `;` are skipped one at a time, so `set p $missing; create_clock ...` still creates the clock. The commands a skipped command ran before the error, such as the iterations of a `foreach` before the failing one, are kept, the file carries on after it, and `constraints.tcl_statement_skipped` warns with its file, line and error. A `source` loop, a statement that never closes, or the reader's time or command limit still fails the read, and the `constraints.tcl_error` warning gives the file, line and error that stopped it.

When the SDC yields no clock period, `synth.sdc_no_clock` warns. If the SDC has `create_clock` commands whose period could not be resolved, the warning says how many, and each one has its own warning with its file and line: `synth.sdc_period_unevaluated` for a period that is not a number, `synth.sdc_clock_unread` for a `create_clock` inside a body the `tokenizer` does not evaluate, or in a command the `tcl` reader skipped before that `create_clock` ran. Otherwise the warning says the SDC has no `create_clock` period.

Set `RTL_BUDDY_CONSTRAINT_READER=tokenizer` to force the fallback, or `=tcl` to require the interpreter and fail if none can start.
